_comment
The WHO SMART Trust artefact index, staged as a top-level directory ahead of becoming its own repository — the same path who-iris is on, and deliberately the same shape. The owner settled the location 2026-09-21, choosing a root-level sibling over folding it into `smart-kg/`: each ingested IG becomes another sibling, and `smart-kg/` already holds judgement methodologies (GRADE), which is a different job. THE INGESTED INDEX HOLDS NO SUBJECT MATTER AND AUTHORS NOTHING: everything under `fhir-artifact-index/` and `docs/` was reconstructed from WHO's published output by `ingest:ig`, and `ingest:ig:check` re-derives it; a hand-edit THERE is a defect, because the next check will either overwrite it or fail. If something is wrong in the index, the fix is in the pipeline or in the upstream IG, never in those files. THAT SENTENCE USED TO COVER THE WHOLE INSTANCE and stopped being true on 2026-09-30, when `themes/` arrived (bean `7h3u`; it moved to `smart-base/themes/` in stage D of the smart-* separation, bean `kg83`, because the theme is the WHO template's, not this IG's): a theme is DERIVED from an upstream stylesheet but is not produced by `ingest:ig`, and `themes.test.ts` re-reads the vendored source rather than a pipeline re-deriving it. Narrowed rather than deleted, because the rule is still exactly right for the two directories it names -- and a whole-instance claim that is true of most of it is the stale-guidance defect this repository keeps paying for.
