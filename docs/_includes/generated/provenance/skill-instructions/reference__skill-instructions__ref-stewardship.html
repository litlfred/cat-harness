Why a GitHub concurrency group is not a window

  • date 2026-09-19
    Measured here, 2026-09-19 (the comment lives in .github/workflows/feature-staging.yml): cancel-in-progress: false governs the RUNNING job, not the pending one, and GitHub cancels a PENDING job when a newer one queues for the same group. Three staging runs from three different branches inside 17 seconds gave two cancelled and one run.
  • bean bean xp5j
    This is the measurement that moved the gh-pages fix from a workflow policy to a steward (bean xp5j): the published site was up to 396.2 minutes behind main across a streak of 24 consecutive cancellations, and no concurrency setting can coalesce the bursts that caused it.
