4. The conversion itself

  • owner-decision 2026-10-14 owner
    **If the remote is empty, push main first.** A repository with work locally can still have an empty remote, and GitHub makes the first branch pushed to an empty repository its default. Run init-folio or push main before any feature branch (litlfred/dth-hrh, owner 2026-10-14).
  • owner-decision litlfred/dth-sc#1 https://github.com/litlfred/cat-harness-tools/issues/1139 2026-10-31 owner
    **If main has no harness yet, land a setup-only PR first.** A fork or an existing repository whose main has no index.config.json and index.lock.json gives the full PR checks nothing to compare against: the base side fails before any test runs, and the PR's own gates are skipped (https://github.com/litlfred/cat-harness-tools/issues/1139). So open one small PR with only what folio_init writes and the pins, merge it, and only then branch for content. Draft-tier checks never build the base, so this does not show until the content PR leaves draft (litlfred/dth-sc#1, owner 2026-10-31).

5. Publishing — provision gh-pages first; an overlay needs it too

  • owner-decision #2417 2026-10-01 2026-10-07 owner
    An overlay never reaches [getting-started](getting-started.md) §5 by itself, so this section repeats the one step a publishing route cannot skip: **provision gh-pages before GitHub Pages is switched on.** Owner, 2026-10-01: "need to create gh-pages branch before can turn on"; repeated 2026-10-07: "need to create gh-pages before can deploy" (issue #2417).

Worked example — litlfred/test

  • owner-decision litlfred/test#3 litlfred/test#5 https://github.com/litlfred/test/pull/5 owner
    ### Worked example — litlfred/test

    litlfred/test is an overlay that remote-mounts its harness layers (its lock is the legacy test.mount-lock.json until it converts to index.config.json and index.lock.json: [index-config](../../kg/kg-core/index-config.md)) and publishes its L1 site from main through a workflow that pushes gh-pages (.github/workflows/l1-kg.yml). Its first plan, in litlfred/test#3, said "Pages source: GitHub Actions" and had no provisioning step. The owner caught it. In [litlfred/test#5](https://github.com/litlfred/test/pull/5) the branch was provisioned as 860f9c2 — an orphan commit holding exactly index.html and .nojekyll, which is what --provision writes.

    Run against that repository today, pages-bootstrap.ts reports gh-pages branch: present on origin and Pages source expected: Deploy from a branch: gh-pages, / (root). Run against a copy whose remote has no gh-pages, it stops at UNPROVISIONED and exits 3, naming --provision — the step the original plan skipped.
