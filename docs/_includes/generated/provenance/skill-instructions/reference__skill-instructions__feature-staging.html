7. The cone — a preview rebuilds only what a changed file can reach

  • owner-decision bean 4j86 2026-10-04
    **Owner ruling, 2026-10-04 (bean 4j86):** "staging rebuild only what is dependency cone of changes (general rule)", at FILE level, with each derived directory's generator declared as writer. A general rule across rendered kinds, not a fact about IGs.
  • history

Before the cone, those last two changes dropped every IG from the preview that existed to review them. staging-cone.test.ts holds all three as tests.

8. The rate limit — a preview never cancels the main site's Pages build

  • owner-decision bean j27s #1868 #1956 2026-10-03
    **Owner ruling, 2026-10-03 (issues #1868, #1956, bean j27s), option 1:** push staging previews to gh-pages less often. GitHub's pages build and deployment keeps only the NEWEST run, so every push cancels the build in flight. A build takes about three minutes (2m20s–3m40s, measured 2026-10-03), and in busy stretches previews were pushed every one to two minutes — ten builds cancelled in a row between 07:50Z and 08:00Z that day, the main site's among them.
  • history 2026-09-19
    Every waiting preview would pend in one group and each arrival would cancel the last — the 2026-09-19 measurement on the stage job.
  • history
    The cleanup and cleanup-dispatch jobs do NOT pass through the gate yet. They push once per closed PR rather than once per push, so they are far rarer; gating them is the next step if cancellations by cleanup are ever measured.

9. Build types — preview and full

  • owner-decision 2026-11-01
    Owner ruling, 2026-11-01: *"preview" = no reindex, only changes, and "full".
  • owner-decision 2026-11-01
    An index is computed over the whole corpus: the search index, the LSI viewer, the SQLite slices, the handler index, and (owner, Q-CI5-1 "B", 2026-11-01) the glossary pages, the translation status pages and the node-kind pages. The cost the owner accepted: a preview of a glossary, translation or node-kind change shows main's copy of those pages, so review such a change on a full build (dispatch with build_type: full) or in its source. Rebuilding an index in a preview shows the reviewer almost nothing and costs minutes, so derive:publish puts back main's copy from main's writer-cone recording and logs borrowed <writer>. The search index was already served from main in a preview (§"Serve the published search index" in the preview workflow).
