A higher instance EXTENDS a role by id — it never edits it (placement PR0b)

  • owner-decision 2026-10-23
    The one exception — a move in flight (owner, 2026-10-23, "Relax the rule"). Moving a role, actor, capability or policy up a layer is two pull requests: the higher layer adds it, then the lower layer removes it, and in between both declare the id. A redeclaration that only adds — every field the lower declaration carries is there unchanged (the same scalar, every member of an array, a nested object by the same rule), and it may carry more, such as the skills it used to add by extension — is accepted with a warning that names the id and both layers, and the higher declaration is used. The warning is the move's to-do: remove the lower copy. A redeclaration that changes or drops anything the lower one said is still refused.
