Readable diagrams: what the research supports

    Owner, 2026-10-31: take what holds up from the BPMN comprehension research and check it mechanically. kg:audit reports each rule below per process (src/workflow/diagram-quality.ts in the tools layer). The sources, and how strong each rule's evidence is, are in the [process-model-quality](../../../methodologies/process-model-quality.md) methodology.
  • owner-decision 2026-11-01
    - Separate routing from work. A task never has two outgoing flows: put an exclusive or parallel gateway after it, or a reader must guess fork vs choice (activity-implicit-split, major). A loop-back INTO a task is fine. A gateway either joins or splits, not both (gateway-mixed). A question is a gateway, never a task: a box named "Should it leave now?" or "Separate this graph?" is a decision drawn as work. If someone must judge first, draw that as a task ("Judge whether it should leave") or a call to Process_AskThePerson, then the question on the gateway after it. - Keep it small. Split by phase into call activities past 20 flow nodes (process-size). That 20 is house style. The only threshold with evidence is 7PMG's 50 (process-decompose, major), and it predicts modelling errors such as deadlocks, not reading speed. - One start event per process level (process-single-start). Several named end events are fine, and the bean CLOSE pattern needs them. - A decision is a question, its branches are the answers (decision-label-question). - Label activities verb-object: imperative verb, then its object (Review the draft, not Draft review) (activity-label-verb-first). The evidence is one study of how ambiguous labels felt (29 students), so this is reported, never gated. - A name says the step, nothing else. No trailing [skill] slug: the skill is in <bootstrap.processes:skill ref>, and the page links it from there (owner, 2026-11-01, Q-RED-3 B). No step numbers ("1 ·", "Phase 2:", "P1.1"): the flows already give the order, and a number in front breaks verb-first. A number that cites a section of a source document goes in the task's documentation. A list of numbered steps is a sign the diagram copies a document's outline; group the steps into phases instead.

When process-size fires, or a diagram has a start event per lane, split it like this:
  • date 2026-11-01
    - The top-level process shows the phases. Each phase is a <bpmn:callActivity calledElement="…"> to its own process. Keep at the top only what moves the work between phases: who hands off to whom, and the decisions that send it back (rejected → revise). A loop that crosses phases is drawn at the top; a loop inside a phase stays in that phase. - A phase lives in its own file, <parent>-<phase>.bpmn, next to the parent, with its own process id (Process_<Parent><Phase>) and a first documentation sentence that says what the phase does. It becomes the phase's row on the publication-workflow page like any other diagram's. - A phase that ends two ways ends in two named end events, and the caller's gateway right after the call reads which one it reached, as GW_BeanYours reads Process_BeanOpen's. - Keep the node ids when you move nodes into a phase. A test, a schema or a skill that points at Task_X then changes only its file and process, not its id. - Open and close the bean at the top, once. A process that is only ever called runs on its caller's bean, so a phase calls neither Process_BeanOpen nor Process_BeanClose (check:bean-calls). "Once" holds for the top as well: a process with several outcomes routes them all into one Process_BeanClose call, which decides itself whether the bean is completed, scrapped or blocked, and only then branches to its named end events. One close per outcome (seven in one diagram, before 2026-11-01) repeats the same box and makes the diagram wide for no reason. - **A caller's adjudication accepts looks one level down.** If the judgement moves into a phase, put accepts on the call to that phase, and take it off any caller further up. - Name a call activity for the phase, verb-object like any activity ("Review the change"), not for its file.
